# Метрики Victory Group Task Scheduler в VictoriaMetrics

Приложение из ДЗ №1 работает в minikube (namespace `task-scheduler`). В namespace `monitoring` Helm-чартами развёрнута VictoriaMetrics. Метрики сервисов, PostgreSQL и RabbitMQ собираются по аннотациям `prometheus.io/*` через service discovery.

## Стек

| Компонент | Что это |
|---|---|
| Приложение | Python 3.12, FastAPI (core-api, ml-worker), воркер на aio-pika (automation-worker), CronJob (review-scraper), React + nginx (web) |
| Хранилище | PostgreSQL 16, RabbitMQ 3, S3 (RustFS) |
| Метрики в коде | `prometheus-client` 0.26, `prometheus-fastapi-instrumentator` 8.1 |
| Экспортеры | postgres-exporter v0.20.1 (сайдкар), встроенный `rabbitmq_prometheus` |
| Мониторинг | Helm-чарты `victoria-metrics-single` 0.48.0 и `victoria-metrics-agent` 0.49.0 (VictoriaMetrics v1.153.0) |

## Установка VictoriaMetrics

```bash
./k8s/monitoring/install.sh      # два helm upgrade --install в namespace monitoring
kubectl apply -f k8s/            # приложение с аннотациями и экспортером
```

- **`vm-single`** (`vm-single-values.yaml`) — хранилище и API запросов на `:8428`, срок хранения 14 дней, том 4 ГБ. Сам ничего не опрашивает.
- **`vm-agent`** (`vm-agent-values.yaml`) — vmagent: находит поды через API Kubernetes, опрашивает их и пишет в `vm-single` по remote write. Принимает push на `:8429`. Сервис назван `vm-single-victoria-metrics-agent`, как в командах задания.

Образы VictoriaMetrics и postgres-exporter берутся с quay.io, там те же образы, что на Docker Hub: CDN Docker Hub в моей сети не отдавал слои.

## Как собираются метрики

```
core-api ×2, ml-worker, automation-worker  :9100/metrics ─┐
postgres-0 → сайдкар postgres-exporter     :9187/metrics ─┤ pull: vmagent каждые 15 с,
rabbitmq-0 → rabbitmq_prometheus           :15692/metrics ┤ цели по аннотациям подов
vm-single                                  :8428/metrics ─┘
review-scraper (CronJob) ── push POST /api/v1/import/prometheus ──► vmagent ──► vm-single
```

**Service discovery.** У подов в шаблоне Deployment/StatefulSet стоят аннотации `prometheus.io/scrape: "true"`, `prometheus.io/port`, `prometheus.io/path`. Job `kubernetes-pods` в vmagent (`kubernetes_sd_configs: role: pod`):
- оставляет только поды с `scrape: "true"` в фазе Running;
- берёт порт из аннотации (`keep_if_equal` по номеру порта контейнера);
- добавляет метки `app`, `namespace`, `pod`, `container`, `node`.

Новые реплики после `kubectl scale` подхватываются сами.

**Порт метрик отдельный.** `/metrics` отдаётся без авторизации, поэтому живёт на порту 9100 (`CORE_METRICS_PORT` и аналоги). Его нет ни в Service, ни в прокси nginx, снаружи кластера он недоступен.

**Push для CronJob.** Под скрейпера живёт пару секунд, vmagent не успевает его опросить. После каждого прогона скрейпер сам отправляет метрики в vmagent (`SCRAPER_METRICS_PUSH_URL`).

## Экспортеры

| Тип (из задания) | Что использовано | Метрики |
|---|---|---|
| Встраиваемый экспортер рантайма | `prometheus-client` в core-api, ml-worker, automation-worker | `process_cpu_seconds_total`, `process_resident_memory_bytes`, `process_open_fds`, `python_gc_*`, `python_info` |
| Экспортер фреймворка | `prometheus-fastapi-instrumentator` в core-api и ml-worker | `http_requests_total{handler,method,status}`, `http_request_duration_seconds` по шаблону маршрута (`/api/v1/tasks/{task_id}`) |
| Готовый внешний экспортер | postgres-exporter, сайдкар в поде `postgres-0`, ходит в БД по localhost | `pg_up`, `pg_stat_database_*` (транзакции, блоки, deadlocks), `pg_stat_activity_count`, `pg_database_size_bytes`, `pg_locks_count` — 339 имён метрик |
| Встроенный в сервис экспортер | плагин `rabbitmq_prometheus` | `rabbitmq_queue_messages_ready`, `rabbitmq_connections`, … — 127 имён метрик |
| Собственные метрики | бизнес-метрики ниже | `taskscheduler_*` |

## Бизнес-метрики

Счётчики увеличиваются после `commit`, поэтому откатившиеся операции не учитываются. Известные значения меток инициализированы нулём: серия видна до первого события.

| Метрика | Тип, метки | Что считает |
|---|---|---|
| `taskscheduler_tasks_created_total` | counter, `source` = user / external / automation | созданные задачи: на доске, из отзывов и AI-черновиков через ml-worker, автоматизациями |
| `taskscheduler_task_moves_total` | counter, `project_id` | перемещения задач между колонками доски |
| `taskscheduler_tasks_completed_total` | counter, `project_id` | задачи, перенесённые в последнюю колонку доски (как бы она ни называлась) |
| `taskscheduler_logins_total` | counter, `result` = success / unknown_user / bad_password | попытки входа |
| `taskscheduler_comments_created_total` | counter | комментарии к задачам |
| `taskscheduler_external_events_total` | counter, `result` = accepted / duplicate | внешние события (отзывы): принятые и отбитые по `Idempotency-Key` |
| `taskscheduler_websocket_connections` | gauge | открытые WebSocket-подключения к доске на реплике |
| `taskscheduler_automation_events_total` | counter, `event_type`, `result` = processed / failed | события задач, обработанные automation-worker |
| `taskscheduler_automations_triggered_total` | counter, `trigger` | автоматизации, у которых сработали триггер и условия |
| `taskscheduler_automation_event_duration_seconds` | histogram | время обработки одного события |
| `taskscheduler_incidents_total` | counter, `result` = created / duplicate / error | вебхуки инцидентов в ml-worker |
| `taskscheduler_llm_request_duration_seconds` | histogram, `mode` = mock / llm | время разбора текста в задачу |
| `taskscheduler_review_scraper_last_run_*` | gauge (push) | последний прогон скрейпера: найдено негативных отзывов, создано задач, ошибок, успех, время |

Примеры запросов:

```promql
sum by (source) (increase(taskscheduler_tasks_created_total[1h]))       # откуда берутся задачи
sum(rate(taskscheduler_tasks_completed_total[1d])) * 86400               # задач закрыто в сутки
sum(rate(taskscheduler_logins_total{result!="success"}[5m]))             # неудачные входы
time() - taskscheduler_review_scraper_last_run_timestamp_seconds > 300   # CronJob скрейпера встал
```

## Проверка

```bash
kubectl get pods -n monitoring
kubectl get svc -n monitoring
kubectl port-forward svc/vm-single-victoria-metrics-single-server -n monitoring 8428:8428
kubectl port-forward svc/vm-single-victoria-metrics-agent -n monitoring 8429:8429

curl "http://localhost:8428/api/v1/label/__name__/values"   # ~990 имён метрик
curl "http://localhost:8428/api/v1/query?query=up"           # 8 целей, все 1
curl "http://localhost:8429/api/v1/targets"                  # цели vmagent и их состояние
curl -s "http://localhost:8429/metrics" | grep 'vm_promscrape_targets{type="kubernetes_sd_configs"'   # up 7, down 0
```
